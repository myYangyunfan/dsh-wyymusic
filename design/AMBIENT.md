# 氛围编程（Ambient）—— 架构与实测台账

「音乐氛围编程」把当前歌曲的氛围铺到**插件面板之外**：对话界面的背景、屏幕左右上角的丁达尔光柱、
窗口最下方的律动条、对话框打字的音符。本文只记**分区与实测结论**——界面长什么样看
`design/shots/plugin-amb-*.png`，逐项设计口径看 `design/UI-PLAN.md`。

## 为什么"突破窗口"要单独设计

插件原本全部活在宿主 `main` 槽里：切到对话界面，`main` 的占用者被卸载，挂在里面的东西
一起消失（这是宿主 slot 的既定语义，不是 bug）。所以氛围必须挂在**另一个扩展点**上：

| 扩展点 | 归属 | 性质 | 实测 |
| --- | --- | --- | --- |
| `shell.overlay` | ui-layout | `list` / `root` 槽，frame 的最后一个子节点，`position:absolute; inset:0; z-index:20`，自身 `pointer-events:none`、直接子元素 `auto` | 切到对话界面后仍在，`.wyy-page` 已消失（harness 里逐帧验过） |
| `main` | ui-layout | `keyed`，同一 id 换页 | 插件面板本体（原有） |

我们的根节点（AmbientLayer，装律动条 / 光柱 / 音符）写了内联 `pointer-events:none`，所以**不挡任何点击**；
它在宿主列之上 —— 光柱的束身正是靠这一点做混合：浅色走 `multiply`（有色光）、暗色走 `screen`，
而不是"盖一张图"。**背景层不在这一层**（见 §B-1）：它插成 frame 的第一个子节点、整层 60% 不透明度
普通合成，靠对话列自身的透明透出来 —— 这条是第六轮推翻"叠色 + 混合"之后定下的形态。

## 三个分区（只通过总线对话，互不 import）

```
A 总线（模块作用域，跨面板/跨会话存活）
  A0 amb          设置：宿主 prefs.json 的 ambient 字段（白名单 + clamp），内存副本先生效
  A1 ambArt       调色板：跟随播放器换歌 → 复用 L3 取色（loadArt 命中缓存，不重扫像素）
  A2 ambAudio     音频：captureStream + AnalyserNode **只读抽头**，rAF 30fps（暂停 12.5fps）
B 效果（各自独立开关）
  1 氛围背景 ambBackdropSync  **插在宿主 frame 最底下的一个节点**（不在 overlay 里）：
    模糊+加饱和的封面（照抄全屏歌词 .wyy-np-bg 那套）+ 取色地板，整层默认 60% 不透明度；
    动的是封面的 transform（缓慢漂移=位置迁移）。其余三样在 AmbientLayer（overlay 层）里
  2 律动条 RhythmBar     72 根柱子 scaleY（频段） + 底沿节拍亮线
  3 聚光灯 Spotlights    左上 / 右上两盏丁达尔光柱（`.wyy-amb-spot` 里 2 个 `<i>`）：
    束身 conic-gradient + mask 沿程衰减，绕灯头摆动，朝向按**屏幕中心**实时算（1.2s 重算）
  4 打字音符 TypingNotes  document 级只读观测 composer 输入 → 光标右上落音符
C 控制（插件页内）
  · 左栏下栏：2 个快捷开关（背景 / 律动条）+ 1 个设置入口
  · AmbientSettings：总开关 + 5 行设置（背景 / 聚光灯 / 律动条 / 音符 / 设置点律动）；**这一页的开关自己随节拍晃动 + 闪光**（功能 3）
```

代码位置（`lib/client.js`）：A 区在「氛围引擎」段（L3 取色引擎之后），B 区 `AmbientLayer`，
C 区 `RailAmbient` / `AmbientSettings`，样式在 CSS 段末尾的「氛围层（app 级）」两小节。

## 成本口径（用户点名要"占内存少的方式"）

| 做法 | 数字（harness 实测） |
| --- | --- |
| DOM 节点 | 77 = `.wyy-amb` 子树全量（72 柱 + 条容器 + 2 盏灯 + 灯容器 + 音符宿主）；背景层另有 3 个节点（root/floor/cover）挂在 frame 下，不在这个数里 |
| canvas | 0 |
| `filter: blur()` | 0（柔边用 radial-gradient 的软收边做，不用全屏滤镜） |
| 每帧写入 | 背景层封面的 transform + 72 根柱子的 scaleY，**只碰 transform**（不重排不重绘） |
| 帧率 | 播放中 30fps（33ms 节流），暂停降到 12.5fps；总开关关掉 = 0 帧 |
| 页面 JS 堆 | 43MB（最近一次 harness 实测；同一页面开着 16MB 的音频流，与开启氛围前同量级） |
| 音频图 | 1 个 AudioContext + 1 个 AnalyserNode + 1 个 MediaStreamSource；**不接 destination**（只读旁支，不影响出声） |

## 宿主侧的实测坑（这些不改代码就会静默失效）

1. **`--dsh-frame-leading-clearance` 在 0.1.7-rc.2 上是空的**：在 `.wyy-amb` / overlay 层 /
   frame 三处 `getPropertyValue` 都读到空串。照抄它做"范围=对话栏"等于挂一个点了没反应的假开关。
   → 改成**运行时量 frame 里最宽的那一列**（侧栏 280 / 中间列 1288 / 右侧栏 0 / 拖拽把手 8px），
   2Hz 重算（切面板、收侧栏都不触发 resize，只挂 ResizeObserver 会停在旧值——实测踩过）。
2. **槽位外面套着 renderer 的包装元素**：`el.parentElement` 不是 overlay 层。→ 用宿主自己的
   `[data-shell-overlay]` 找层，再用 `layer.parentElement` 拿 frame。
3. **`captureStream()` 在"刚 play 那一刻"拿到的是 0 音轨的空流**；同一首歌播到十几秒后再建图
   `max=106` 立刻有数。→ 挂不上就 260ms 重试（≤12 次）；挂上了但频谱**恒全 0**（不是"音乐安静"）
   攒够 1.5s 就重挂一次（每首歌 ≤3 次）。harness 里正是靠这次自愈拿到 `peak=194`。
4. **composer 没有公开的插入点回调**：只有 `data-lexical-editor` / `data-composer-input` /
   `data-composer-card` 这类 DOM 标记。音符效果因此**只读观测**：document 级 `input` 事件 +
   原生 Selection 量光标框，节点挂进我们自己的层——不碰宿主 DOM 一个节点。
   输入法合成期（`compositionstart/end`）不出音符，连打按密度上限（45–240ms）截流。
5. **输入框卡片自己半透明还不够**：`[data-composer-card]`（`.BuPN2G_card`，底色 `--dsw-specific-input-major`）
   底下垫着 `.D_tfqW_composerSeat` —— `background:linear-gradient(180deg, transparent 0px, var(--dsw-alias-bg-base) 36px)`
   且 `position:sticky;bottom:0`。它才是"下方那条白板"。**认它不认类名**（类名是构建哈希，会变）：
   从卡片往上走，第一个 `background-image !== none` 或底色不透明的祖先就是它。
6. **代码块的底色全走令牌**：`.md-code-block` 根上 `.block` 自己声明
   `--dsl-code-block-background: var(--dsw-alias-markdown-code-block)`，`pre` 与 `pre.shiki`（`!important` 那支）
   都用它；`.bannerWrap` 用 `--dsw-alias-bg-base`，内层 banner 用 `--dsl-code-block-banner-background-color`
   → 行内芯片走 `--dsw-alias-markdown-inline-code`。所以想让代码块"透"，**改令牌**比改颜色稳
   （同理：令牌的变化会自动传到 shiki 的 `!important` 分支）。

## 反证（每条"它能"，都配一条"它不能"）

- 总开关关掉 → overlay 里柱/灯/音符宿主**都不存在**，背景层节点也被摘掉（关着还铺一层 = 开关是摆设）。
- 关掉律动条这一路 → 柱子消失，而背景层仍在（证明两路真独立）。
- 范围=对话栏 → 条子 left=280；范围=整窗 → left=0（证明范围不是假设置）。
- 非 composer 的输入框打字 → 不出音符（网页别处也有 contenteditable）。
- 连打 6 次 → 只出 1 个音符；音符到点必须自己消失（不留残留节点）。
- 抽头 `ok` 但电平恒 0 → 必须触发重挂，而不是"绿着不动"。
- 通用"融入"体检：同一副"圆角+浅底"装扮的 `<button>` 不许被标；**深底**（彩底）行内芯片不许被洗。
- 输入框底板：带标记（半透明渐变）vs 把宿主原样（不透明）涂回去 —— 同一像素**差 ≥30**，
  证明底带透出来的真是背景，不是"颜色碰巧像"。
- 品牌行三连：队列为空时必须 `disabled`（不是"按了没反应"）。
- 暗色主题：把封面**强制成纯白**（构造最坏情况）→ 正文对比度仍 ≥4.5（黑纱兜底，不是碰运气）。

## 动效口径（按 onetake 的规则做的第二轮）

参照 onetake（github.com/feitangyuan/onetake，PolyForm Noncommercial 1.0.0）里那套**实测**动效规则，
把氛围动效接进了仓库既有的缓动词表（`--ease-snap` t80≈.22 / `--ease-spring` / `--ease` / `--t-slow`）。

| 规则 | 之前 | 现在 |
| --- | --- | --- |
| 曲线分角色，别一条 smootherstep 套到底 | 原始电平直接乘进位移（频谱一跳背景就跳） | **振幅快起慢落包络**（0.30 / 0.08 每帧）+ **运动包络**（重音顶起、0.065/帧松弛、落在 0.18 的静止底） |
| 画面不能永远在动（rests） | 背景一直在均速漂 | 运动集中在拍上，拍间近乎静止 —— 判据"6s 内存在 ≥250ms 近静止窗"，实测 **1056–1419ms**（随歌曲电平波动） |
| >80px/帧 无快门即频闪 | 无闸 | 位移按 **%/帧** 设上限（封面 0.35 %/帧，尺寸缓存 + 换算，绝不逐帧读 offsetWidth）；判据线 ≤40px/帧 且 ≤2400px/s，实测峰值 **45–54px/s**、单次最大 **7.5–8.3px** |
| 频谱是"跳"不是"抖" | 直接写原始频段 | 逐柱**快起慢落**（0.55 / 0.16 每帧）+ 单帧上限；实测单次最大 scaleY 变化 **0.22**（判据线 0.25） |
| 换拍必须 carry，不能替换 | 换歌 = 取色**一帧硬切** | `@property --amb-c1..4-l/-d` 注册成 `<color>` + `transition: … var(--t-art,1000ms) var(--ease-art,…)`；判据"中间态 ≥4 个、400–2500ms"，实测 **6–8 个 / 1583–1633ms**；反证：注入 `transition:none` 后该腿必须红（1 个 / 0ms） |
| 入场要有曲线 | 挂载即出现 | 条子淡入（`--ease-snap`）—— 淡入只能挂在子元素上，**给层根加 opacity 会把光柱的 blend 关进自己的组**；音符入场 snap + squash + spring 收束 |
| 动效得是有意的（可让路） | 无 | `prefers-reduced-motion: reduce` → 背景漂移冻结（不跑 rAF）、音符关闭、节拍闪光熄灭；harness 用 CDP 模拟该偏好验过 |

动效 oracle 落在 `scripts/harness-ambient.mjs`（判据沿用上一轮动效腿的口径：速度按 **document.timeline
的 rAF 钟**算，位移 ÷ 时间；反证用"注入 `transition:none` 必须让 continuity 腿变红"和"人为瞬移必须让
curves 腿变红"两条）。

## 第六轮（2026-09-28 深夜）：背景层按用户点名的形态重做

用户否掉了"在顶上叠色团再混合"那版："直接把全屏歌词的背景调一个 60 的不透明度，塞在整个底下"。

**先量再改**（这决定方案可行性）：宿主 `body`/`frame` 有**不透明白底**，而对话那一列
（`centerCol` / `[data-conversation-session]` / `[data-conversation-scroll]`）的底色**全是
`rgba(0,0,0,0)`**，侧栏与输入卡各自带底色 ⇒ **把自己插成 frame 的第一个子节点就会透过透明列显示**，
不需要任何 blend、不碰宿主节点、不挡点击。

落实：`ambBackdropSync()`（非 React，模块作用域）在 frame 上 `insertBefore` 自己的 `.wyy-amb-bg-root`
（`cover` + `floor` 两层，形制照抄 `.wyy-np-bg` / `.wyy-np-ground`），整层 `opacity:var(--amb-strength,0.6)`；
换歌时取色走同一条 `--t-art/--ease-art`；漂移只写封面的 transform 且单帧 ≤0.35%；
`prefers-reduced-motion` 下**保留静态背景、只停漂移**（听 matchMedia 变化，背景层不在 React 树里）；
React 重渲染可能把新节点插到我们前面 ⇒ 2Hz 自查 `frame.firstElementChild === node`，掉了就塞回去。

顺带修掉重构带出来的一个真 bug：**自家两层（背景层 / overlay 层）也是 frame 的子节点而且更宽**，
"取最宽的一列当对话列"的算法会把它们当成对话列 ⇒ 范围设置永远算出 left=0。两处测量都显式跳过自家节点。

新增守卫：背景层必须是 frame 首个子节点且不在 overlay 里、带 filter 的元素**恰好 1 个**（背景那个静态 blur，
不是逐帧滤镜）、reduced 下静止、动效腿加"动过的帧 ≥10"防**空跑变绿**；另出浅/暗两张截图
（`plugin-amb-conversation.png` / `plugin-amb-conversation-dark.png`）。

## 第七轮（2026-09-29 凌晨）：真的"铺满整页" + 中文输入法出音符

**用户复报两件事**：① 背景"只有上方那个板块有"；② 打拼音后点候选选词，不出音符。

### ① 现在知道"谁在画底"了

像素采样把话说死了：对话列左缘 y=12% 与底色差 23（有色），y=35/62/85% **差 0（纯白）** ——
不是层没插进去，而是**宿主在对话列里另有一个大面积的不透明白底把它盖住了**（那块"上方板块"
是它没盖到的部分）。所以背景层的最后一块拼图是：**运行时找出谁在画底，让它临时让开**。

做法（不写死任何 hash 类名）：在对话列取三个采样点，`elementsFromPoint` 自上而下找**第一个不透明、
且覆盖 ≥60% 列宽 / ≥50% 列高**的元素，把它背景改透明（原值记账），卸载/关闭时原样还回去；
卡片、按钮、正文因为不够"大"一律不碰。2Hz 自查里再让一次（切视图/换主题后宿主会重新画上）。

### ② 浅色不能直接用全屏歌词那套地板

`npFloor` 是给"深底浅字"的全屏歌词配的**深色**地板；拿它铺浅色页面，正文对比度实测掉到 **4.07**。
于是按主题分档（这是编程界面，可读性是硬约束）：

| 主题 | 地板底色 | 封面模糊 | 白纱 | 实测（左缘四点） |
| --- | --- | --- | --- | --- |
| 浅色 | 取色 `band`（亮调） | 0.32 | 42% 白 | 底色 255 → 采样 [180,197,192]，对比度 **10.4** |
| 暗色 | `npFloor`（同全屏歌词） | 0.55 | 无 | 底色 [21,21,23] → 采样 [40~63,52~79]，对比度 **8.2–12.3** |

守卫改成**像素级**：把 CDP 截屏画进 canvas，采样对话列左缘四点，①与页面底色差 ≥12（证明铺满）
②按 WCAG 算正文对比度 ≥4.5:1；**浅色与暗色各跑一遍**（`背景铺满（浅色/暗色）`、`背景不破坏正文对比度（…）`）。

### ③ 中文输入法选词不出音符

Chromium 提交候选时 **`input` 早于 `compositionend`**，而 input 那边看到 `isComposing=true` 就跳过了
—— 于是"打拼音 + 点候选"一个音符都不出。改成**两个信号都认**：组字过程（`isComposing`/composing）
一律不出，**提交那一刻**（compositionend）出一个；提交后浏览器补发的那条 `input` 由密度上限挡掉。
smoke-client 里两条用例正反都量（组字中 0 个、提交后 1 个、补发不重复）。

## 第八轮（2026-09-29）：聚光灯改成**丁达尔光柱**

用户要的是"能看到丁达尔效应的**渐大光束**"，不是我那版一团柔和光晕。改法（零新增节点）：

- **束身** = `conic-gradient` 在灯头处切一个 16° 窄窗（`transform-origin` 落在灯头 x）——
  往下自然渐宽，这就是丁达尔；**沿程衰减**用 `mask-image: linear-gradient(to bottom, .92 → transparent 86%)`。
- **亮芯** = `::after` 再来一层更窄（6.5°）更亮的光，`mask` 收到 70% —— 芯 + 束两层才有体积光的芯晕关系。
- **灯头** = `::before` 椭圆 + bloom。
- **合成按主题分**：浅色底上 `screen` 等于冲白（看不见）⇒ 束身走 **multiply 做"有色光"**、亮芯走 screen；
  暗色两处都 screen。实测截图：暗色光柱非常清楚（`plugin-amb-conversation-dark.png`），浅色是偏淡的有色束。
- 摆动仍是 rotate（灯头为原点，左右扫），束宽随重音呼吸 `scaleX(1→1.08)`（单帧 ≤0.02）；reduced 下不摆。

守卫新增一条结构判定：两盏束身都必须是 `conic-gradient` + `mask` 不为 none + 亮芯也是 conic（也就是
"**是光柱不是光晕**"），外加原有的在位/在摆/关掉即消失三条。

## 第十三轮（2026-09-28）：点进度条/歌词"直接跳到曲首" —— 待定 seek 被换歌带进新资源、钳到末尾

用户带回来的现场证据只有一行诊断：`{"target":104.6,"rs":1,"seekable":1,"got":0,"tries":1,"result":"ok"}`
—— **诊断说 ok、播放头在 0**。这行本身就是第一个结论：旧的成功判据（写进去了 / 收到 seeked）不是成功。

1. **两处旧判据的假绿**（裸元素探针实测，不是读代码推的）：
   - 「赋值成功 = 跳成功」：`a.currentTime = dst` 的读回是同步的，可它只是**待定** seek；
     P5 对照里 `after.ct=8.2`（想要 138.3）就是这么来的。
   - 「收到 seeked = 跳成功」：E1/E2 实测，seek 落地后 60–90ms 重置 `src`/`load()`，播放头被**静默冲回 0**，
     而 `seeked` 早已 fired、`data-seek` 一路写着 ok。
   现在成功只有一个定义：**播放头真的在目标上、而且站得住**（±1.5s 落点复核 + 900ms 守望）。
   站不住按代价恢复：重跳 → 带 `fresh=1` 重拉一次流（绕开宿主 5 分钟取链缓存）补跳 →
   认输时把走时同步回真实播放头 + 明说跳不过去（不再让 UI 停在假目标上）。

2. **用户那行的成因（产品级竞态）**：点下去那一刻 `state` 已切到新曲、而 `<audio>` 还装着旧曲
   （取链是 fetch = 宏任务，几百毫秒窗口）。旧实现在这个窗口里把**按旧曲算出的绝对时刻**写给旧元素，
   浏览器把这条**待定 seek 带进新资源**、**钳到新曲末尾**：
   探针 R1（换歌 +0ms 点 70%，旧曲 313s）实测 `seeked@1258ms ct=130.6`（= 新曲全长）
   → `ended@1260` → **自动跳下一首**（t3000 已经在第三首的 1.5s 处）—— 用户看到的"跳到曲首"就是这一串。
   修法两条：① **元素装的不是这次点击那首就先不写**，等它真装上这首再落；② **比例为准**：
   按点击比例 × 元素**真实时长**折算（条上的总时长可能是列表 interval 兜底或换歌那一瞬的旧值）。
   改后同一探针：R1 绝对时刻 218.7 → 实落 91.3（=70%×130.6）；R2 落 88.1（=70%×126.1）；
   R3 落 190.8（=70%×272.6），三条都站住、`ended` 不再出现。
   （**顺手挖出一个真 bug**：上一轮改名把 `a.currentTime = t` 留在了 `seekAttempt` 里 —— `t` 成了 i18n
   翻译函数 → `TypeError: ... non-finite`，所有 seek 静默失效、`data-seek` 恒为 null。
   教训：机械改名必须配一条**运行时**的腿，静态检查看不出来。）

3. **harness 补一条端到端的腿**（7a-2，用户形状）：队列抽屉里挑"一短一长"，先点短曲（预热取链缓存），
   再点长曲当"上一首"，然后在**同一个同步块**里"点短曲那行 + 点进度条 70%"。
   实测：点下去时元素装着「后来」338.1s（id=254524，ratio=0.699），落到「意中人」81.2s／目标 80s
   （点击目标元素实测 114.6s；**若按旧曲的绝对时刻会落到 237s** → 钳位 → ended → 自动换歌）；
   1.8s 后仍在原曲（81.2 → 83.0s）。
   反证写在这条腿的判据里：`0.7×长曲 > 短曲全长` 不成立时**直接判前置不满足**（白跑不算绿）。
   **这条腿第一版自己写坏了**：`settle()` 只测"在播 + rs=4 + ct>0.3"，而刚点下去时**上一首也满足**这些，
   于是基准时长取到了上一首（126.1s），把**正确的落点**（81.1 = 70%×114.6）判成了红的（差 7.2s > 容差 6s）。
   现在等的是"**元素真的装上这首**"（sid 换人 + 标题对上 + 数据到位），并再等 1.6s 让流式 MP3 的时长估计收敛。
   收尾还把开局那首点回去 —— 后面的像素腿取的是"当前歌曲的色"，这条腿不该改别条腿的前置：
   第一次跑就是它把暗色·纯白封面那条对比度腿踩红的（4.22 < 4.5，换回开局那首后 61/61）。

四条腿：i18n 通过 / host 18/18 / client 47/47 / harness **61/61**。
