# dsh-wyymusic 视觉方案 v2 —— 三层色彩 + 中文排印系统

> 评审对象：本文件 + `design/proto.html` 可运行原型（真实网易云数据、真实封面取色）。
> 结论：**当前界面"没有设计感"不是配色不够红，而是缺了两样东西——大面积的动态色彩，和一套排印刻度。**
> 本方案补齐这两样，并把"Spotify 感"落到可验证的数值上，而不是抄个灰色。
>
> 状态（2026-09-28 刷新）：本方案已落地。逐条差距实例与实测数字见 `design/UI-GAP-LEDGER.md`，
> 氛围编程各轮的实测结论见 `design/AMBIENT.md`；本文件里§12 的差距数字是 09-27 的快照。

## 1. 诊断：上一版为什么会平

| # | 症状 | 实测证据 | 根因 |
|---|---|---|---|
| 1 | 全篇只有灰，没有"饱和色" | `grep -c "font-family" lib/client.js` → 0；深色令牌里除 `--wyy-accent` 外无一个彩色 | 只抄了 Spotify 的**灰阶**，没抄它的**色彩来源** |
| 2 | 红色到处出现，反而不显眼 | `.wyy-round-btn / .wyy-chip / .wyy-card-play / 选中态` 全用同一个 `#ec4141` | 品牌色被当成**装饰色**用。Spotify 的绿色只出现在 1 个控件上 |
| 3 | 层级靠"猜" | 卡片 `#f7f7f7`、hover `#efefef`、rail `#f7f7f7` 三处几乎同值 | 没有表面阶梯（surface steps），Spotify 的层级是**由表面色阶递进表达，不用阴影** |
| 4 | 文字发挤、字号零散 | `.wyy-h3{letter-spacing:-.3px}`、`.wyy-pl-name{letter-spacing:-1px}`、出现 11px / 11.5px 字号 | **中文不能负字距**；11px 低于 Windows 可读下限（Fluent 最小 12px）。Spotify 的"紧"是字体本身的特性，它的令牌表里根本没有 letter-spacing |

**核心认知修正**：Spotify 的饱和色不是画在按钮上的，是**从专辑封面提取后铺在大面积表面上**——页面头部色带、全屏播放页的底光。我上一版把这一整层（L3）完全漏掉了。

## 2. 三层色彩模型

| 层 | 名称 | 由谁决定 | 用在哪 | 禁止 |
|---|---|---|---|---|
| **L1** | 品牌色 | 固定：网易云红 `#ec4141` | 主播放键、选中态、"已红心"、进度条 hover | 不做背景、不做正文色、不做卡片底色 |
| **L2** | 表面色 | 固定灰阶，浅/深各一套 | 页面底、卡片、hover/press、文字阶梯、分隔线 | 不随封面变化（保证稳定感） |
| **L3** | 艺术色 | **运行时从封面像素提取** | 头部色带、快选磁贴、全屏歌词底光、播放条染色、"正在播放"卡片 | 不用于正文文字、不用于小图标 |

一句话：**L2 负责"这是一个产品"，L3 负责"这一屏是这张专辑"。** 两者分开后，红色才重新变成稀缺信号。

L3 的六个令牌（每屏一次提取，写在 `.wyy-page` 上）：

```
--art-band      色带顶色（浅=粉彩化 / 深=压暗降饱和）
--art-vivid     纯艺术色（磁贴渐变、NP 底光、发光描边）
--art-deep      深色端（色带渐变终点混色、阴影色、播放条）
--art-wash      NP 右下角互补底光
--art-tint      极淡染色（浅色主题播放条、卡片 playing 态）
--art-on        色带上的文字色（由 WCAG 对比度算出，不写死）
```

```

```

| 角色 | 字号/行高 | 字重 | 用在哪 |
|---|---|---|---|
| meta | 12 / 16 | 700(标签) 400(值) | eyebrow、计数、时长 |
| sm | 13 / 20 | 400 | 副标题、歌手名 |
| body | 14 / 22 | 400 | 正文、曲目行 |
| sub | 16 / 24 | 500 | 区块副文案 |
| card | 17 / 24 | 600 | 卡片标题 |
| sec | 20 / 28 | 700 | 区块标题 |
| title | 26 / 34 | 700 | 面板标题 |
| head | 34 / 42 | **800** | 色带大标题 |
| lyric | clamp(24, 3.4vw, 38) / 1.28 | 700 | 大屏歌词 |

规则：
- **`letter-spacing: 0` 全局**；只有全大写拉丁 eyebrow 用 `+0.08em`。中文大标题靠**字重**不靠字号，更不靠负字距。
- 数字一律 `font-variant-numeric: tabular-nums`（时长、进度）。
- 正文行高 ≥1.5（中文 1.6 最舒服），标题 1.2–1.35。
- 汉字与拉丁/数字相邻时留 ≤¼ em 空隙（浏览器已自动，禁止为"紧凑"而加负距）。

### 3.4 间距 / 圆角 / 动效

```
间距 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64      （基数 4）
圆角 4(小) · 6(封面) · 8(卡片) · 12(主容器) · 999(胶囊/圆钮)
动效 100ms(状态) · 200ms(悬停) · 320ms(入场/换色)  ease: cubic-bezier(.3,0,0,1)
层级：靠表面色阶递进，不用 box-shadow（封面浮层上的按钮除外）
```

## 4. L3 取色引擎（`design/palette.js`，已实测）

**流程**：封面 `<img crossOrigin="anonymous">` → 中心方形裁切 → 56×56 canvas → `getImageData` → 色相直方图 → 色调映射 → 写 CSS 变量。

关键参数（对齐 AndroidX Palette / node-vibrant 的公开数值）：

| 环节 | 取值 |
|---|---|
| 采样 | 56×56 = 3136 px，中心裁切（四角常是留白/文案） |
| 上下文 | `willReadFrequently:true, alpha:false` |
| 过滤 | 跳过 alpha<250；丢弃 L≤0.05 与 L≥0.95；s<0.08 归入中性桶 |
| 分桶 | 36 桶 × 10°，占比 <1.5% 视为噪点 |
| 色相平均 | **向量平均**（sin/cos），避免 350°+10° 抵消成 0° |
| 打分 | `0.24·population + 0.52·saturation + 0.24·luminance` |
| 目标 | vibrant s≥0.35 / muted s≈0.30 / dark L≈0.26(≤0.45) |
| 深色降饱和 | `s×0.78 ∈[0.14,0.62]`、`L×0.42 ∈[0.12,0.32]`；浅色粉彩化 `L∈[0.66,0.82]` |
| 文字色 | WCAG 相对亮度实算，**必须让 12–14px 副标题也 ≥4.5:1** |

**实测数据（8 张真实推荐封面，headless Edge，1600×1000）**：

| 封面 | 浅色色带 | 对比度 | 深色色带 | 对比度 |
|---|---|---|---|---|
| 欧美万评优质女声 | `#a3cabe` | 10.03:1 黑 | `#376c5b` | 5.57:1 白 |
| 前奏一响起 | `#c19cb1` | 7.39:1 | `#563347` | 9.83:1 |
| 助眠辑·自然音 | `#d29cc5` | 7.94:1 | `#762d64` | 8.27:1 |
| 0.8x哭完了吗 | `#c497b2` | 7.19:1 | `#5a2e48` | 10.04:1 |
| 你曾经有多认真 | `#c29ead` | 7.50:1 | `#5b3846` | 9.18:1 |
| 打工人必备·嘻哈 | `#c398b1` | 7.21:1 | `#502a40` | 11.03:1 |
| 想听民谣 | `#cea1a3` | 7.90:1 | `#713236` | 8.71:1 |
| 「日系」中毒 | — | 封面未加载 → 回退 L2 | — | 回退生效，页面无灰块 |

- 16 个（8 封面 × 2 主题）色带**全部 ≥4.5:1**，无一例需要人工兜底。
- 性能：**冷启动 2.64 ms/封面，热路径 0.29–0.56 ms**（图片解码缓存后）。一次进入歌单详情最多 1 次提取，快选区 6 次 ≈ 3 ms。
- 网络前提（已实测）：`p1/p2.music.126.net` 返回 `Access-Control-Allow-Origin: *` 且不校验 Referer ⇒ **不需要新增图片代理路由**；`?param=500y500` 可把 47 KB 压到 18 KB。

**降级矩阵**（三条路径都验证过）：

| 情况 | 行为 |
|---|---|
| 封面加载失败（`onerror`） | 保留 L2 中性令牌，色带退成极淡品牌红 |
| 画布被污染（`getImageData` 抛 SecurityError） | 同上，并记录 `failures[url]='画布被污染'` |
| 提取全为中性（黑白封面） | 用 `gray` 桶推出色带（低饱和），文字仍按实算对比度选 |
| DSH 主题切换 | **不重新提取**，只用已有 swatch 重跑色调映射（<0.1 ms） |

缓存键 = `封面URL + 主题`；提取放在 `requestIdleCallback`，不阻塞首屏。

| **搜索** | 结果标签 = 胶囊 chip（surface-2，选中才用品牌红）；空态用骨架 shimmer 而非空白 | `--wyy-surface-2`、`--r-pill` |

**必须一并修的工程问题（已实测确认）**：
- 重置规则用 `:where(.wyy-page button)`，否则 `(0,1,1)` 会盖掉所有单类彩色按钮（上一版就是这样把红钮洗成透明的）。
- DSH 主题判定继续用 `body[data-ds-dark-theme]`，插件不自带主题开关。
- 播放中状态（`<audio>` + state）留在模块作用域，色带令牌随"当前曲目"变化但**不随面板卸载丢失**。

## 6. 落地顺序（4 个可独立回滚的提交）

1. **令牌层**：把 §3 的四组令牌写进 `client.js` 的 CSS 顶部，删掉所有硬编码色值与负字距。纯替换，风险最低。
2. **取色层**：移植 `design/palette.js` 到 `lib/client.js`（约 200 行，无依赖），加 `--art-*` 写入与缓存/降级。
3. **色带 + 磁贴**：发现/详情/排行/我的四屏接色带；快选磁贴逐个取色。
4. **播放条 + 全屏歌词**：`--wyy-bar-bg`、`--np-*` 令牌与歌词排版刻度。

每步都用同一套 headless Edge 脚本截图 + 断言（0 页面异常 / 0 console.error / 0 网络≥400 / 色带对比度 ≥4.5）。

## 7. 怎么评审原型

```bash
node design/serve.mjs            # http://127.0.0.1:55899/
# 右上角「取色面板」= 实时打印每张封面的 band/vivid/wash/deep/highlight + 对比度 + 黑白字判定
# 右上角太阳/月亮 = 切换浅色(网易云) / 深色(Spotify)，走的就是 body[data-ds-dark-theme]
```
数据是 `design/fetch-data.mjs` 从插件真实接口抓的（12 推荐 / 10 自建 / 8 榜单 / 3 份曲目表 / 1 份歌词结构）。
**歌词只保留"每行字数 + 时间戳"结构**，正文用自写占位文案按同分布填充——不把受版权保护的歌词落进设计产物。

## 8. 明确的取舍

- 不做：渐变文字、彩色阴影、玻璃拟态、多色相调色板。饱和色只来自封面。
- 不做：为"更像 Spotify"而把浅色主题也压成灰白——浅色保持网易云的轻快，深色才承担 Spotify 的厚重。
- 风险：网易云若给封面域名加上 CORS 校验，L3 会整体退化为 L2（界面变素但不报错）。已留 `failures` 观测点，一旦大面积失败可加宿主侧代理。

## 9. 验收记录（§6 第 3、4 步已落地，实测）

判据不是"读代码觉得对"，而是**屏幕像素**：把字形涂透明 → CDP 截图 → 页内把截图画进 canvas 取每行的真实底色（渐变底加取 p05/p95），再按 WCAG 算比值。色带/磁贴另加三条结构判据（本块面必须带**自己的**成对令牌、令牌值不得等于样式表里的 L2 兜底、磁贴字区与封面矩形不相交）——只测对比度会让"取色整体失败、全场吃兜底色"静默变绿。

| 测量点（两套主题各跑一遍） | 通过 / 采样 | 最差比值 |
|---|---|---|
| 发现页 色带 + 8 块磁贴（浅） | 12/12，遮挡 0 | 4.57:1（磁贴 4.57–6.5） |
| 发现页 色带 + 8 块磁贴（深） | 12/12，遮挡 0 | 5.68:1 |
| 排行榜 色带（浅 / 深） | 4/4 / 4/4 | 13.44 / 7.04 |
| 我的 色带（浅 / 深） | 4/4 / 4/4 | 9.91 / 11.49 |
| 歌单详情 色带（浅 / 深） | 6/6 / 3/3 | 9.47 / 12.33 |
| 歌单详情 播放条 + 曲目行（浅 / 深） | 22/22 / 22/22 | 5.27 / 5.27 |
| 全屏歌词 正文与元信息（浅 / 深） | 9/9 / 10/10 | 5.29 / 4.05 |
| 全屏歌词 表面地板（浅 / 深） | 280 / 280 行 | 未唱 5.29·当前 17.76·已唱 3.29 / 未唱 4.09·当前 17.18·已唱 3.15 |

- 全部四趟：**0 页面异常 / 0 console.error / 0 网络≥400**，磁贴 8/8 各自带成对令牌（浅、深）。"已唱"行按大字号 3:1 判定，实测 3.15–3.29（有意压暗，余量较薄，是设计取舍不是漏检）。
- 界面多语言 88 条文案 0 处表外中文字面量；冷启动语言持久化在**零次点击语言按钮**的前提下通过。
- **守卫反证**（守绿不算证据，能抓住才算）：色带标题强制 `#ffffff` → 像素判据红（1.2<3）；`--art-band` 强制成 L2 兜底 → 结构判据红（画面上看不出差别，但取色其实没发生）；摘掉磁贴成对令牌 → 结构判据红；磁贴封面放大回 76px → 几何判据红（字区右缘 804 > 封面左缘 793）；整条色带 `display:none` → 结构判据红。五类全部命中。

### 验收过程中量出来的真缺陷（都已修）

- **磁贴字压封面**：76px 封面 + 76% 字宽时两框重叠 33px，字落在照片像素上 ⇒ `--art-on-tile` 的 4.5:1 当场作废。改成 56px 封面 + 58% 字宽，并把它变成守卫里的几何不变量。
- **判据与实际墨色不一致**：判定用的"黑"是 `#171717`，画上去的是 `#101012` —— `#d04986` 被判成"黑字 4.25 不达标"而换成白字，实际只有 **3.87:1**。现在判定与画面共用同一组墨色常量，且不达标就把面色明度挪出 WCAG 死区（实测 `#b06a2c`：黑 4.49、白 3.90，两边都不够）。
- **无色封面被判成"取色丢了"**：黑白/灰度封面（中心 64² 里有彩像素 0）在 `extractArt` 里提前返回 null，`buildArtTokens` 早就写好的中性分支永远走不到。现在 6 张这类封面实测都产出了令牌（`gray` 计数 2→6，`empty/threw/tainted` 全 0）。
- **采样窗越界**：被列表裁掉半边的磁贴，字框右缘伸到面外，采样条右端落在页面底色上（实测 `bg=#ffffff`），把一块达标的面误判成不合格。采样窗改为"字框 ∩ 全部裁剪祖先 ∩ 视口"（§11 有 A/B 反证：同一次布置下旧公式 1.09:1 报红、新公式报绿，且白字白底仍被抓）。
- **流程自身的假绿/假红**：轮询"封面图已加载"当取色结论（封面加载只是前置条件，实测因此把一块 6 秒后就染好的面判成 L2）；切视图后先读"上一个标题"再点（React 渲染更快时永远等不到变化）；新 profile 首启的 API Key 弹窗遮罩会盖住整页（守卫正确地拒绝测量，却被误读成"没采到字"）。

## 10. 怎么复跑这套验收

**仪器自身的两条纪律（都是踩过假红/假绿后加的）**：
- **取样前等过渡收敛**（320ms）：上一趟把 `color` 还原回去，带 `transition: color` 的元素会从 transparent 渐变回来；紧接着跑的第二趟会读到过渡中的中间色（实测把 `.wyy-lang` 读成 `rgba(231,197,198,.24)` → 1.49:1 的假红）。
- **取样行裁到"真正被画出来"的区间**（自己的矩形 ∩ 全部裁剪祖先的 client 盒 ∩ 视口）：横向滚动容器边缘外的那截根本没画，落在容器外底色上的中位像素会把一块达标的面判成不合格（实测 1.09:1，见 §11）。被整块裁掉的实例**跳过并计数**（`被裁跳过 N`），不许静默缩样本；跳过多少必须能被断言（`__pcmeta.clipped/narrowed`），否则"clamp 生效"和"clamp 把一切都跳过了"在报告里长得一模一样。
- `pixexpect` 步骤专门用来做**必须变红**的反证：只有在仪器如实报出含指名 key 的不达标时才算 PASS。

## 12. 原型 vs 实物 逐键对齐（第三轮，实测）

用户判据从"像不像"升级成"**你设计的一样吗，一一列出来**"。这一轮不再靠眼睛对比截图，
而是把两边 DOM/CSSOM 摊平成**同构指纹**再逐键 diff，产出可执行的差距账：**`design/UI-GAP-LEDGER.md`**。

### 12.1 仪器

`%TEMP%/wyy-fingerprint.js` 一个页面内只读探针，原型腿和插件腿**共用同一份**（这是"同构"的全部含义：
两侧观测同一组选择器、同一组属性，任何一侧改选择器都要同步改另一侧，否则 diff 出来的就是仪器差）。
两个细节决定了这份指纹能不能用：

- CSSOM 侧必须读 `declared()`（作者写下的公式），不能只读计算值。
  `padding: calc(var(--dsh-frame-top-clearance,Npx) + var(--s-N)) var(--s-N) var(--s-N)` vs
  `var(--s-N) var(--s-N)` 在计算值上长得一样（都是几个 px），**差距会被折叠掉**。
- `expect` 步骤按真值判红，所以诊断函数**失败时返回 false、成功时返回描述字符串**，
  旁边再挂一条 `eval` 打印原始状态 —— 否则"什么都没测"会静默变绿。

### 12.2 账

| 口径 | 修前 | 修后 |
|---|---|---|
| 逐屏逐键实例（raw，含实时数据差） | 204 | 206 |
| 归一化后（纯数据量差异折成同一条） | 178 | **175** |
| 恰好消失集（降级成数据差 = 已不再是差距） | 26 | **31** |
| 归并后的差距键位 | 52 | **46** |

7 个视图配对（发现 / 排行榜 / 我的 / 搜索 / 歌单详情 / 全屏歌词 / 第二个歌单详情），每屏一节，杜绝跨屏错配。
46 个键位的去向是**穷举而不是举例**：B 类（宿主面板比整页窄 99px，线性导出）9 键位 **47** 实例、
C 类（数据量与当次真实曲名，原型吃快照）21 键位 **86** 实例、D 类（有意偏差）8 键位 **26** 实例、
F 类（状态与原型 fixture 坑）8 键位 **16** 实例 —— **47+86+26+16 = 175**，与归一化总数恰好对上；
键位 9+21+8+8 = 46 同样对上。E 类（故意不做）2 项不在指纹里：原型有、上游接口没有的能力，diff 抓不到。
**剩下真正该改的都在 A 类，且已改完。**

### 12.3 A 类里最有价值的一条：最近播放副行永远空着

三层独立缺陷叠在一起，每一层单独看都"合理"，所以一直没人发现：

1. 客户端 `playFrom` 建源时**没带** `playCount/creator`（详情页两处、榜单一处）；
2. 就算带了，宿主 `cleanRecent` 的白名单只留 `id/name/cover`，**落盘即丢**；
3. 就算落盘了，`PlaylistGrid` 还会为没话说的条目渲染一个空 `div`，顶着 4px 上边距把卡片撑出半行空白。

修完的实测：`副行 4/6 张（有量并说出量的 3 张，空元素 0 个）`，盘上 `playCount=30775274/34834012`，
而**旧条目仍只有 id/name/cover** —— 后半句是关键：它证明这些字段是这次写进去的，不是本来就有（否则这条断言在任何一版上都会绿）。

### 12.4 这一轮又被抓住的假绿/假红

- **显示切片当存储上限**：判据写"存了 6 条"，而 6 只是发现页 `slice(0, 6)`，上限是 `RECENT_MAX = 8`。
  改成"置顶 + 去重 + 上限"的**转移**判据（实测 `n=7，位置 1 → 0`）。
- **反证空过**：主判据还红着就断言"不存在的 id 必须判红"，等于什么都没测。现在要求主判据先绿。
- **jsdom 全局桥**：客户端半边的 DOM 测试用 `new Function('window','document','fetch','require', src)` 求值，

  `ReferenceError`，而这条**只在真渲染时炸**，静态检查和其他用例都看不出来。`Image` 同属一类（没桥就走 `loadArt`
  的 6s 超时→重试→null→L2 兜底，正好是设计里的降级路径，所以也不报错）。补桥后 `smoke-client.mjs` 25/25，

- **持久化语言把守卫判红**：`prefs.json` 里留的 `lang=en` 会让所有按中文文本找元素的步骤 MISS。
  腿的第一步现在显式钉 zh（实测 `lang=zh（点了 0 次）`）。
- **冒烟腿把测试数据写进了用户真实的 `~/.dsh`**（隔离红线被自己的仪器破了）：
  `smoke-client.mjs` 把宿主半边挂进本进程，而宿主的落盘目录是 `process.env.DSH_HOME || ~/.dsh` ——
  不覆盖它就会**真写** `~/.dsh/wyymusic/prefs.json`。证据：19:36:10 那次 mtime 变化，且条目里带着
  本轮刚加的 `playCount` 字段（说明是新代码写的，不是历史遗留）。
  现在腿开头显式设 `DSH_HOME=%TEMP%/dshhome-official`（复用它已有的扫码 cookie，没有就另起临时 home 并**只读地拷一份**，永不回写）。

### 14.1 残留的"点了跳回曲首"：不是 seek 丢了，是**片头署名行本来就住在 0 秒**

上一轮修的是"元数据没到位时 seek 被浏览器静默丢掉"（`PENDING_SEEK`）。用户复测仍然"有点"回曲首，
剩下的这一撮有确切来源：网易云 LRC 的**头几行是署名**（作词/作曲/编曲/制作人），时间戳就是 `[00:00.000]`。
它们本来就在曲首，点它们**等于**回曲首 —— 而且一首歌常带 2~4 行，随机点一下命中率不低。

改法（`LINE_SEEK_MIN = 0.05`，`client.js:1449`）：`t ≤ 0.05s` 的行不给 handler、不给 `role=button`、
`cursor:default`，即 `.wyy-np-ly.plain`。同时歌词自动滚动在指针进入列表时冻结（`onPointerEnter → stopScroll`，
`onPointerLeave → 重新贴近当前行`），否则你瞄准的那一行会被滚走 —— 看起来也像"点错了地方"。

**这条腿原来是空跑的**：整条腿上只有"全屏已开 / 已收起"两个断言，其余 seek 只被记录、没被判。
重写成 10 条判据（`%TEMP%/trace-run5.log`，86 步，**断言失败 0 条**）：

| 操作 | 判据 | 实测 |
|---|---|---|
| 全屏条 25% / 10% | `seeked` 落点 ≈ 目标比例 × duration | 41.02 / 41.0；16.41 / 16.4（164s） |
| 播放条 50% | 同上 | 81.99 / 82.0 |
| 填充段内 8%（命中子元素） | 同上 | 13.26 / 13.1 |
| 歌词第 7 行（当前第 2 行） | 落点比点前前进，且**高亮行 == 点的那一行** | 18.85 → 41.70s，高亮行 7/32 |
| **第 0 行（片头行）** | 类名含 `plain`、无 `role`、窗口里 **0 条 seek 事件**、时间只前进不倒退 | `wyy-np-ly past plain` / role=null / 0 条 / 44.17 → 47.90s |
| 键盘 ← / Home / End | 落点 ≈ 按键前 t−5 / 0 / 按键前 dur−1 | 10.62/10.7；0.01/0；162.99/163（随即 `ended` **正常**换下一首） |
| 换歌 700ms 就点条 | 只许往前走或不动 | 0.39 → 83.06s（直接落到 81） |

**反证**（同一台仪器，把第 0 行改回"可点 + `currentTime=0`"）：一次报出 5 条不合格 ——
`时间倒退了 47.91s`、`2.4s 只走了 -45.45s`、`还是发了 seek 事件：seeking@0 seeked@0`、类名没了 `plain`、role 变回 button。
仪器能红，上面那一片绿才算它量出来的。

**这一轮仪器自己错了三次（全是假红）**，都记下来，因为假红会让人去改本来对的东西：

1. `.wyy-track-fill` 只盖住轨道的一半，`clickRatio(…, 0.9)` 量的是**填充段自己的** 90%，落在轨道上是 **46%** ——
   于是判"落点 75.98s 与目标 147.6s 差 71.6s"。产品没错：`164 × 46.3% = 75.9`。
   现在目标比例一律以**整条轨道**为基准换算（`__ratioLocal`），并自检换算结果必须落在元素自身的 5%~95%，
   落不进去就当场报"这一下点在轨道上了，没碰到要测的东西"。
2. `End → go(d−1)` 只离曲尾 1s，歌**立刻放完** → `ended` → 自动换下一首；判据却拿按键**之后**新歌的
   300.7s 当分母，差 136.7s 全是自己造的。现在对着**按键那一刻**的 duration 算，并把"正常走完"显式记成
   `触发ended:true`（不是"退回去"）。
3. 从 0.88s 按 ← ：`go(max(0, cur−5))` 落在 0，和"根本没跳"在时间轴上长得一样 —— **零样本**。
   现在 ← / Home 必须在曲中测（按键前 t ≤ 5.5s 直接判"样本是空的，落点和没跳分不开"），End 排最后。
4. （顺带）填充条判据从"≈ 目标比例"改成"≈ 当前 t/dur"：填充条是**活的**，2.4s 采样窗里它自己又走了 1.5%，
   旧判据的差值恒等于 1.5% —— 白测。
5. 上一版三条轨道跳的"证据"也是空的：`clickRatio` 只把鼠标移过去，`clickSel` 点的是**元素中心**（≈50%），
   而歌本来就在 ~50%。新增 runner 步骤 `clickSelAt`（按元素内比例点，比例可以是**页面现算的表达式**）后才成立。

### 14.2 动效：抄 onetake 的**机制**，不是它的调子

`github.feitangyuan.onetake` 不是配色库也不是曲库，是一套**剪辑纪律**。四条直接可用：

- **Never replace a beat — carry it.** 每个画面边界上都要有东西活到下一拍，并且**看得见地移动过去**。
- **Never let the frame be always in motion.** 停顿才让爆发立得住。
- **Moves from the library, curves chosen by t80.** 曲线不按手感挑，按 t80 / 峰值斜率分档。
- **Fast moves need the shutter.** 超过 80px/帧（30fps）会频闪成"好几个分身" —— 反过来当**速度上限**用：
  80px/帧 @30fps = **2400px/s**。

这个插件上真正的两个 carry：**全屏开场/收起**（播放条那张 56px 小封面 → 647×538 的大封面，同一张图飞过去）
和**队列抽屉**（从按下那一点长出来）。

| 决策 | 依据（量出来的） |
|---|---|
| 行程 **852px**（欧氏；曼哈顿 1178） | FLIP 反置前后实测的两点距离 |
| 软下限 **355ms** | 852 ÷ 2400px/s |
| 曲线按**峰值斜率**挑：`--ease` 4.04 / `--ease-snap` 5.26 / `--ease-spring` 4.11 / `--ease-art` 2.73 | 对 cubic-bezier 做数值微分取峰值，不靠手感 |
| 新增 `--ease-glide:cubic-bezier(.25,.1,.25,1)`（峰值 2.29、t80=.50，匀） | 1s 走完 852px ⇒ 预测峰值 **1950px/s**，对 2400 留 19% 余量 |
| `--t-art` 900 → **1000ms** | 上面那条反推出来的 |
| 封面全程 `opacity:1`，地板/文字另起一层 320ms 淡入 | "它此刻**就是**播放条那张" —— 飞行途中淡出会把它变成"另一个东西" |

最后一条带出一个结构改动：`.wyy-np` 原来是"一层带渐变背景"，现在把地板（渐变 + 模糊封面）挪到
**绝对定位的兄弟层** `.wyy-np-ground`（grid 容器的绝对定位子节点不参与栅格，布局不动），
于是地面 320ms 淡、封面 1s 实心飞，互不绑架。副作用一处：走"沿祖先链找不透明底色"的对比度扫描
（`wyy-sweep.js`）要改成认这一层，否则全屏里的文字会被判成"底下什么都没有"。

**动效 oracle**（`%TEMP%/wyy-build-steps-motion.mjs`，逐帧采样，四条 beat + 反证，`%TEMP%/wyy-motion-r11.log`，**7/7**）：

| beat | 判据 | 实测 |
|---|---|---|
| 全屏开场 | 首帧落在播放条那张上（≤8px）/ 峰值 ≤2400px·s⁻¹ / 时长在带内 | 起手偏差 **0px**、峰值 **1925px/s @67ms 窗**（单步 1945px/s @33ms）、**1114ms** |
| 队列抽屉 | `transform-origin` 距按下点 ≤12px / 峰值 ≤2400 / 时长 ∈[100,600] | 原点距按下点 **0px**、**278ms** |
| 全屏收起 | 末帧落回播放条那张（≤8px）/ 峰值 ≤2400 | 收尾偏差 **0px**、峰值 **1939px/s @50ms 窗**、**1025ms** |
| 按压反馈 | 按住 **≤3 帧**看得见变化（帧数判，ms 只报）/ 松手回位 | 按下 **38ms / 隔 1 次几何更新**、2.2px 变化、残差 **0px** |
| 反证 | 给 `.wyy-np-art` 打 `transition:none`，开场那条必须红 | 起手偏差 **852px**、峰值 **0px/s@0ms**（窗塌了也判红）→ 红 ✓ |

速度尺怎么量、为什么不能按 rAF 读数直接算、以及"帧数判延迟"的由来，见 §14.4（这台 oracle 的第三次修正）。

**这台 oracle 也修过三个假绿**：① 四条 beat 的判定先用 `dump` 输出 —— 而 runner 的 `dump` 是固定页面转储、
**求值表达式被忽略**，于是四条全被记成"非空 = PASS"（假绿），改成 `eval` + `expect` 真值判定；
② 按压延迟最初从录制开始计时，量到 85ms —— 那里面混着 CDP 往返；改成从页面自己的 `pointerdown` 起算，
实测 32ms（并且顺手堵掉"负数也算过"的漏洞：负延迟现在显式判失败）；
③ 速度尺用连续钟给量化的几何打时间戳（r7/r8 两趟假红 2543/2518px·s⁻¹）—— 见 §14.4。

### 14.3 换主题那 1–2 秒：一次像素扫描出两套，底和墨必须同一帧翻（第六轮，实测）

**问题。** 换主题不是"重画"，是"换调色盘"。只要有一块表面已经翻了、另一块还没跟上，中间就会撞出读不出的
颜色。这条最先由 r4 量到：播放条掉到 **4.13:1**（底 `rgb(212,207,209)`、墨 `rgb(95,95,102)` @`.wyy-bar-sub`，
低于 4.5 的窗口 50ms / 2 个样本）。当时的处理是"等法太急"——把死等 900ms 改成**连续 3 次读数相同**
（`SETTLE`），红就没了。但「红没了」不等于「病没了」，它也可能只是被采样窗躲过去了。所以这一轮先改**机制**，
再用四条反证把机制钉住。

**机制：一次像素扫描出两套，主题翻转只换引用。**
`extractArt` → `buildArtPair` 一次算出浅/深两套，`artStyle`（`lib/client.js:1195`）把 16 个**源令牌**
`--art-*-l` / `--art-*-d` 写进元素行内；主题块只做一件事——把**活跃令牌**指到当前那一套：

```
.wyy-page,.wyy-art{--art-band:var(--art-band-l);--art-tint:var(--art-tint-l);…}
body[data-ds-dark-theme] .wyy-page,body[data-ds-dark-theme] .wyy-art{--art-band:var(--art-band-d);…}
```

于是 **换主题 = 级联里换一次引用**（同帧、零延迟、不碰网络），**换曲 = 源令牌在过渡表里滑 1s**。
两件事在物理上分开，各自可测。

| 决策 | 为什么（量出来的） |
|---|---|
| 过渡表只挂**源令牌**（16 项，`client.js:2826`） | 活跃令牌是 `var()` 引用、每帧跟随；挂上去等于滑两遍 |
| 墨（`--art-on-l/-d`）**不进**过渡表 | 旧那版给墨押了个延迟（`0ms 时长 + 0.42×--t-art`），实测 **3.29 / 3.89**、窗口约 100ms。反证 D 把这个机制重测了一遍：迟延确实生效，色带一路掉到 **1.24:1** ——「两支墨在底附近交叉」的地板，比旧注释记的 4.17:1 还低 |
| 派生令牌（`--np-wash-a/b`、`--wyy-bar-bg`）不进过渡表 | 它们是活跃令牌的 `color-mix()` 派生物、跟着插值走；挂上去是"二次滑动" |
| 两块面的底 = **当前主题的底 × 当前主题的艺术色** | 浅色条 `color-mix(--art-tint 18%,--wyy-bg)`（`2807`）、深色条 `color-mix(--art-deep 18%,--wyy-bg)`（`2865`）、选中行 `color-mix(--art-tint 8%,transparent)`（`3081`）——底和墨同源，才不会出现"新主题的底配旧主题的釉" |

**四条反证**（每条都要求**同一把尺子**变红，并且拒绝"没采到样本"冒充红）：

| 反证 | 打的是什么 | 实测 |
|---|---|---|
| A 底没跟着主题翻 | 浅色那套的色带底钉成深色那套（深→浅那趟） | 色带 **3.63:1**（窗口 **547ms**，整窗只有一个底值）→ 红 ✓；播放条 6.16 / 选中行 5.00 **仍绿** ✓ |
| B 调色盘迟到 | 浅色那套的 tint/deep 钉成深色那套（浅色态） | 播放条 **4.13:1**（窗口 1394ms，底 `rgb(212,207,209)`）——与 r4 屏幕上的读数**逐字相同** → 红 ✓；色带 11.83 / 选中行 5.00 仍绿 ✓ |
| C 滑动被掐掉 | `--t-art` 按成 0ms，再换一曲 | 色带中间值 **0 个 / 0ms**（一帧到位）→ 红 ✓；撤回后滑行恢复（15 个 / 798ms） |
| D 墨押后 | 活跃墨挂 380ms 时长 + 420ms 迟延（旧实现的形态），浅→深那趟 | 色带 **1.24:1**（窗口 **806ms**；「墨停在 `rgb(16,16,18)`」的帧 23 个、其中 9 个低于 4.5）→ 红 ✓；播放条 6.16 / 选中行 5.51 **仍绿** ✓ |

B 这条反证的**因**是校准过的，不是猜的：先量了一张 4 组合 × 2 主题的可行性矩阵（探针 6，稳态）：

| 组合 | 浅色（条 / 行 / 带） | 深色 |
|---|---|---|
| S0 基准 | 6.16 / 5.80 / 7.66 | 8.56 / 5.57 / 8.81 |
| S1 老占比（72/30/70，不迟到） | 5.67 / 5.27 / — | 8.29 / 5.33 / — |
| S2 老占比 + 迟到 | 1.24 / 1.01 | 8.54 / 1.21 |
| S3 产品占比 + 迟到 | **4.13** / 5.00 | 8.70 / 4.66 |

这张表钉死两件事：① **致红的是"迟到"，不是占比**（老占比单独跑一格都不红：浅 5.67 / 深 8.29）；
② 同样"迟到"，**只有浅色态有判据**（深色 8.70 是绿的——白字在深底上怎么拉都够）。所以 B 只在浅色态立，

**正式腿的读数**（腿：`%TEMP%/wyy-build-steps-ink.mjs`，148 步 / 123 条表达式 → `%TEMP%/wyy-ink-r9.log`；

|---|---|
| 正式 1 浅→深（产品机制） | 色带最低 **4.8:1** @777ms、换底 **1 次**、落在中间态的帧 **0**；播放条 6.16、选中行 5.51；窗 1258ms |
| 对照 0 稳态（不动任何东西） | 色带 11.83 / 播放条 6.16 / 选中行 5.80 |
| 对照 1 换曲 | 色带滑行 **15 个中间值 / 765ms**（等新色 200ms） |
| 对照 2 滑行窗 | 播放条 6.17 / 选中行 5.8 / 色带 11.83，低于 4.5 的窗**都是 0ms** |
| 像素对比度 | 采样 33/33、实测 33、遮挡 0 |

同一条腿独立跑过两遍（`-r8` / `-r9`），读数稳定：反证 B 两次都是 **4.13:1**（连底 `rgb(212,207,209)` 都一致）、
反证 D 的红窗 784 / 806ms、正式 1 的色带最低点都是 **4.8:1**。所以上面这些不是"某一次碰巧"。

**仪器学到的四条（都踩过）：**

- 收敛判据不能只看令牌：`.wyy-bar` / `.wyy-row.active` 自己还挂着 `--t-slow` 的 `background` 过渡，
  令牌停了它们还在动。`SETTLE` 因此读的是**最终落在屏幕上的计算值**（令牌 + 三块面的 background）。
- 采样窗会被"点设置对话框"那次重渲染吃掉：r6 第一次跑出来的 `flips` 是
  `{"n":0,…,"bgs":["rgb(61,122,41)"]}`、窗只有 551ms——翻转之前一个样本都没有。修法是把对话框
  **在开窗之前**打开，并在窗里插一段 `wait 700`。
- 反证必须能**独立塌陷**（A 只塌色带、B 只塌两块面）。做不到这一点，反证就只是"整页花了"。
- 反证的自证要**轮询到稳定**：反证 B 第一版同步读令牌，读到旧值 → 自己判自己"没生效"（自证假红）。

**健壮性注记（环境，不是产品缺陷）。** 取色要走网易云 CDN：这台机器上偶尔把 6s 超时 + 一次即时重试全吃满
（探针 7 实测：`data-art` 停在 `pending`、`diag.timeout` +1、两张封面都 `hang @6001ms`；同一张 URL 第二次
走 `artCache` **9ms** 就出）。这段时间面板停在 L2 兜底调色盘上——兜底本身是安全的（同一把尺子实测播放条
**6.23** / 选中行 **5.83**），所以不是"读不出"，是"没有艺术色"。验收腿因此改成等**结论态**（`ok`/`none`）
而不是等固定秒数；取色腿另外允许**换一行歌催一次**（`WAIT_ART_OK`，`kicked` 会记账）。

### 14.4 动效 oracle 的第三处假红：速度尺量的是"rAF 读数"，不是**动画自己的时钟**（全量回归那轮，实测）

**症状。** 全量回归时 `beat 全屏开场` 红：`峰值速度 2543px/s（>2400 = onetake 的频闪线）`。而同一份产品
在上一轮是绿的（2182px/s）。红的那两趟（r7/r8）与绿的几趟之间**产品没改过**，改的只是机器负载。

**先排掉"产品飞快了"。** r7 红的那趟：峰值 2543px/s，但**单帧最大位移反而更小**（63.9px vs 上一趟的 85.7px）。
产品真加速的话，逐帧步长先变大 —— 现在的现象是反的。加一条诊断把逐帧原始几何摊出来（不改判据）：

```
r8 实测：帧数 81，帧间隔 min/中位/max = 4.8 / 16.7 / 50 ms
  最快 53ms 窗 TOP5：25ms 窗 64.0px → 2518px/s ｜ 27ms 窗 64.6px → 2367 ｜ 47ms 窗 93.6px → 1991
  逐帧速度序列（t=111→368ms）：405 · 444 · 950 · 700 · 846 · **2051** · 1225 · **2663** · 1346 · 1415 …
```

**机制（两个钟不同源）。** 几何是**动画自己按帧网格算出来的**（`document.timeline`，本机实测间隔就是
干净的 16.6/16.7/16.8/33.3ms），而 `performance.now()` 是连续钟，读点落在 4.8~50ms 不等的 rAF 上。
用连续钟给量化的几何打时间戳，短窗就会把"两格的位移挤进一格"：25ms 窗读成 2518px/s，而**同一段 70ms
聚合只有 138.6px ÷ 70ms = 1980px/s**（= 设计值 852px ÷ 1000ms × 峰值斜率 2.29 = **1951px/s**，差 1.5%）。
也就是说：产品一直在自己的曲线上，是尺子把采样抖动记成了速度。

**改法（两把尺子，都按动画时间轴量）。**

| 尺子 | 窗长 | 线 | 干什么 |
|---|---|---|---|
| 宽窗 | ≥40ms（≈2.4 显示帧） | 2400px/s | 频闪线（onetake：80px/帧 @30fps） |
| 细窗 | ≥12ms（≈1 显示帧） | 2400px/s | **瞬移探测器**（原来那条"单帧 >120px"作废） |
| 原始 px 步长 | — | 不判，只报 | 会被宿主掉帧放大，见下 |

窗长不足 40ms 直接**判红**（`最快窗只有 N ms（<40ms，量不出速度）`）—— "什么都没测"不许变成全绿；
反证里那条 `transition:none` 正是踩在这个退化上判红的（峰值 `0px/s@0ms` + 起手偏差 852px）。

**为什么细窗不能按"px>120"判（r10 实测的宿主掉帧）。** r10 那一趟宿主前 500ms 掉帧，时间轴间隔是
`49.9, 16.7, 116.7, 83.3, 50, 83.3, 66.7, 66.7, 16.6, …`，最大单步 **158.2px 落在 83.3ms 上 = 1900px/s**
（产品干净那趟单步是 64.8px / 16.7ms）。同一段帧两把尺子的对照：

```
按 px 判：158.2 > 120 → 红（假红，那是宿主掉帧）
按速度判：158.2px ÷ 83.3ms = 1900px/s < 2400 → 绿 ✓
```

**同一趟里还修了按压判据。** `按下到看得见` 原来判 ms（>40 判红）：干净那趟 40ms、r10 掉帧那趟 77ms，
**两次都只隔 1 次几何更新** —— ms 阈值量的其实是宿主的帧率。产品自己的规矩就是"按住 ≤3 帧有变化"，
所以判据换成**帧数**（按下之后到变化那一帧之间，几何真的更新了几次），ms 只报。r11 实测 **38ms / 1 次更新**。

**读数（同一份产品，五趟对照）。**

| 趟 | 连续钟（旧判据） | 动画时间轴（新判据） | 结论 |
|---|---|---|---|
| r7 | 2543 → 红（当时就是判据） | — | 假红 |
| r8 | 2518 | — | 假红（诊断那趟） |
| r9 | 3238 | **1939px/s @50ms** | 换钟后立即绿 |
| r10（宿主掉帧） | 2039 | 1900 @83ms（旧 px 尺判 158.2 红） | 掉帧不再假红 |
| r11 | 2795 | **1925 @67ms / 单步 1945@33ms** | 绿（7/7） |

注意 r9/r11 的**连续钟读数仍然 >2400**（3238 / 2795）—— 这不奇怪：它是连续钟里最坏的那个短窗，
正是旧判据假红的来源。新判据在同一趟里给出的是**平顶**（r9 的 TOP5：1939 · 1931 · 1930 · 1925 · 1921，
跨度 50~83ms），即"仪器安静下来"的样子。

**纪律（给以后写速度判据的人）：** 量几何的时间戳必须与算几何的时钟同源（动画 → `document.timeline`）；
窗长不得短于一个显示帧；"量不出来"（窗太短 / 样本为 0）判红不判绿；新尺子要拿同一段**录制帧**回放对拍
（旧尺红、新尺绿，且理由说得清是掉帧还是产品）。

### 14.5 仪器比产品先过期：改名（单令牌 → 成对令牌）之后的两种"红"（全量回归那轮，实测）

全量回归先红了两批，**两批都不是产品的问题**，各记一条纪律。

**① 探针还在问旧名字（a18 light / dark 各 9 条红）。** 第六轮把取色层改成双调色盘后，元素上写的是
**带后缀的源令牌**（`--art-band-l/-d`、`--art-on-l/-d`、`--art-tile-l/-d`、`--art-on-tile-l/-d`），
无后缀的 `--art-band` 只在样式表里做引用（`.wyy-art{--art-band:var(--art-band-l)}`）。而 a18 腿的
`BAND_DYED` / `TILES_DYED` / `waitDyed` 和守卫 `wyy-bandguard.js` 都还在读无后缀名 ⇒ 读到空串 ⇒
判"这块面没染色" ⇒ 转去查旁证"封面到底能不能取到" ⇒ 封面可达且 `data-art=ok` ⇒ 记成
**"取色层/缓存把它丢了"**。红的样子很自洽（整批面一起红、两条主题各红一份、`data-art` 全是 ok），
恰恰是"尺子问错了问题"的签名 —— 真丢色时 `data-art` 会停在 `pending`。

修的是尺子，并且**顺手变强**（三条都不许省）：

| 判据 | 旧 | 新 |
|---|---|---|
| 自带取色 | `--art-band` / `--art-tile` 非空 | `-l` 与 `-d` **成对**都在（缺一套 ⇒ 换主题时会掉回 L2） |
| ≠ 兜底 | 与本主题的 `.wyy-page` 兜底比 | 与样式表里那条**与主题无关**的兜底规则里的**同名牌**比（`--art-band-l` / `--art-band-d`） |
| 主题接线 | —（没有这条） | 活跃令牌（计算值）= 同元素同后缀的**计算值**：`.wyy-art` 的引用链一断，色带会画出**页面的**调色盘 |

第三条比的是"计算值 vs 计算值"，不是"计算值 vs inline"：`.wyy-page` 那条 `transition:--art-band-l…` 的
过渡表只挂在 `.wyy-page` 自己身上（过渡不继承），`.wyy-band/.wyy-tile` 换色是**瞬时的**，所以这里没有
"滑行中读到中间值"的假红窗口 —— 但换成比 inline 就会把这个窗口引进来，别改。

**② 兄弟腿留下的主题（tilecp 2 条红，其中一条还是"反证必须红"）。** tilecp 的判据（容器外是白底 ⇒
浅字应报 1.09:1 ⇒ 旧公式必须红）只在**浅色态**成立，而它不自己钉主题 —— 链上前一条腿正是 a18 dark。
结果整条腿在深色下跑：`复现条件=英文档·浅色·发现视图 => false`，紧接着 `反证B·旧公式必须报红`
也红（深底浅字当然不红）。**"前一条腿跑完是浅色"不是前置条件，是运气**：现在它照抄 i18n 腿的做法，
开头自己点 `设置 → 浅色` 再断言。同理，语言也是跨轮残留（i18n 腿早已钉过）。

机制值得记一笔：宿主把主题选择**写回**了隔离 home 的
`profiles/web/cordis.patch.yml`（`ui-theme` 的 `config.preference`，实测该文件 mtime 随"点主题"而动，
最后落成 `preference: light`）。所以"换一个浏览器 profile"躲不开这个残留 —— 残留不在浏览器里，在宿主配置里。

**纪律：** 腿必须在开头把**自己依赖的全局状态**（主题、语言、视图）钉住并断言，钉不住就红在"钉"这一步；
红灯的形状要能和尺子的盲区对上（整批同时红 / 数据里出现"不可能的组合"），对上了先怀疑尺子 ——
但**改尺子要同时给出"为什么产品是好的"的证据**（这里：改完探针，同一批面直接报出两套源令牌 + 活跃令牌，
证明取色从头到尾都在）。

### 14.6 差距账的三处"绿得可疑、红得没理"：混合年份的输入 / fixture 快照的不变量 / 零样本的绿（全量回归那轮，实测）

全量回归把 §12 那条链整条重跑，第一趟（r5）出来的三个数（raw 101 / 归一化 85 / 恰好消失 16）比上一版
差出一大截。逐条查下去，**产品一点没错**，是仪器自己的三条毛病；每条都配了个"以后再犯必须红"的判据。

**① 假绿：下游读到的是上一轮的指纹（混合年份）。** 重跑命令把两条 cdp 腿的输出**收进了链日志**，
却没刷新 `wyy-fp-<side>.log` —— 而 `wyy-fp-extract.mjs` 读的正是这两个文件。于是"这一趟"的 diff 是
**proto 侧 19:10 的指纹 × plugin 侧 19:14 的指纹**：两侧连**视图数**都不同（日志里 `fingerprints: 7 … / 4 …`），
diff 只对得上 4 屏，"恰好消失"从 31 掉到 16，三个数全是假的 —— **而五个桶照样全 0，没有任何断言在问"输入是哪一年的"**。

两条纪律（都立住了）：
- 链里每条腿**只写它下游真正读的文件**：现在链逐腿把 cdp 的 stdout 落成 `wyy-fp-<side>.log`，截图目录也逐趟带戳
  （顺带修掉一个更早的漏：截图目录此前没加临时目录前缀，6 个 `wyy-shots-fp-*-rN` 漏进了仓库根 —— 已搬回 `%TEMP%`）；
- **同构要有条数的判据**：两侧指纹数必须相等（本次 `7 × 7`），不等即红。把"混年份"从"事后对数字"变成"当场报错"。

**② 假红：不变量钉在"某次 fixture 的快照值"上。** fp 腿的收尾断言写死 `if (a.length !== 6) return false`
（最近播放历史 6 条）—— 而 6 只是**发现页的显示切片**（`slice(0, 6)`），存储上限是 `RECENT_MAX = 8`，
盘上真实 7 条。拿显示切片当存储上限，这断言从写下的那一刻就是红的，和产品无关。

修法不是把 6 改成 7（那还是快照），而是**转移判据**：动手之前先拍前置快照（`window.__preRecent`），
断言只问"新项置顶 + 无重复 + 不超过 8 + 条数 = min(前置 + 0|1, 8)"。实测
`n=7（前置 7）first=欧美万评优质女声•萦绕耳畔忆于心间`。**有状态存储一律这么判**：绝对条数是仪器的快照，
转移（Δ 与上限）才是产品的行为 —— 这条在 §12 的 A9 里已经吃过一次亏，这次是**腿自己**又犯了一遍。

**③ 零样本绿：绿了，但绿在"什么都没发生"上。** 转移判据第一次跑就绿 —— 因为它点的"第 0 张卡片"
正是最近的播放项：**点了等于没点**，"新项置顶"那一支天然成立。**能过判据的动作必须真的改变状态**：
现在挑 `名字 ≠ 前置[0]` 的卡片，实测 `OK card pick=欧美万评优质女声•萦绕耳畔忆于心间`（不在榜首）。
另配一台**逻辑电池**（`%TEMP%/wyy-fp-rulerlog.mjs`）：把断言表达式抽出来，喂 8 份**合成状态** ——
3 份正确（去重置顶 / 新增 +1 / 满员截断到 8）必须绿，5 份坏的（错置顶 / 有重复 / 多出条目 / 超上限 /
缺前置快照）必须红，实测 **8/8**。一趟真跑只走到一个分支，合成状态能把其余分支和"坏账"一起验。
（电池自己也先红过一次：stub 的键名写成 `preRecent`，而表达式读 `window.__preRecent` —— 尺子必须先被尺子验过。）

**这一轮的新四个数**（同一份产品，产品文件 mtime ≤ 00:35:32，所有腿在 01:0x 之后跑）：
raw **209** / 归一化 **178** / 恰好消失 **31** / 键位 **47**；比 A 轮 +3 实例 / +1 键位，出处逐条对上 ——
`band.box[]` 6→7、`np.box[]` 1→2（都在几何 **2px 容差**边缘进出）与 `np.onColor`（新键位，`rgb(24,24,24)` vs
`rgb(245,245,245)`，与 `np.blurBg` 同一条设计决定：全屏 = 封面底光 + 浅墨）。
台账里的键位表这一轮改成**成员显式列出**（49+82+29+18 = 178、9+20+11+7 = 47，两处都恰好对上），
以后每趟回归按同一口径重算，不再出现两轮之间"键位搬家"却对不上账的情况。
